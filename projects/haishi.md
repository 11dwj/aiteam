# 项目总结：海事解封报告智能体（haishi）

> 长江（江苏段）海事封航后的**解封疏导决策辅助系统**，服务对象为各海事分支局值班长/值班员。本总结自包含，无需查看源码。
> 版本演进：Python 研发版（LangGraph + Chroma）→ **Java 交付版（JDK8 零依赖单 JAR，当前主力，SVN jyhs/ai/java）**，两者 HTTP 接口一致、行为对齐，同一 bug 两边都要修。

## 一、业务全貌

把《放行策略矩阵》（2422 行知识库，19 个真实案例校准）变成可运行的解封决策辅助系统：

1. 输入封航事件（原因/级别/气象实况/台风/船清单/未来 3 天预报，可部分留空由系统推断）
2. 规则引擎按 **4 封航原因（大风/大雾/暴雨/施工）× 4 管控级别（Ⅰ 最重~Ⅳ 最轻）= 16 格策略矩阵**路由
3. 解禁前置硬性核查（不达标 → 建议暂缓 hold=true；**前瞻放行**：按预报窗口复核值可提前给方案，标注"以该时刻实测复核为准"）
4. 触发 30+ 条条件追加规则；RAG 检索历史相似案例（Java 版：60 条预计算向量内存余弦，无向量库）
5. 生成 **3 套解封策略**：推荐方案·大船优先（gold）/ 效率优先 / 分区域减堵点，按 7 维度粗线条描述批次（严禁船名 MMSI）
6. **风险点位推演**（需 risk_cases 输入）：规则算术打底（相似度匹配+强度修正）→ LLM 深化（网格/时间窗/概率，代码侧约束校验）→ 段级热点回流进策略编排
7. 输出《解封疏导方案》公文（HTML / .doc，**模板组装不调 LLM**——卡片所见即公文所出）

**定位红线**：系统只做"建议 + 推演 + 记录偏差"，最终由值班长决断（叙事者收尾段固定以此结束）。

## 二、多专家架构（Java 版当前形态，9 月演进而来）

**核心原则：规则先行，LLM 兜底**——能算的不调 LLM（分类/核查/时间锚定/风险算术全规则）；LLM 只做规则做不了的研判与编排，输出强约束 JSON + 代码校验/修复/回退三重防御。

7 位专家（experts.json 注册，conf/ 外置热加载可关）：analyst 分析师（规则先行+LLM兜底+置信路由）、weather_parse 气象解析（缺数值才调）、rag 案例检索（纯向量）、ai_strategy 策略生成（3 套并行）、comparison 案例对比、risk_forecast 风险推演（规则打底+LLM深化）、narrator 叙事者（思考流 3 段第一人称转写，只准转述 facts）。

一次请求管线（典型 10~15 次 LLM 调用）：输入规整（①②③）→ 规则引擎④ → 预报窗口⑤（三套共同锚点，铁律6.1 首批不得早于它）→ 风险推演前置⑥（热点注入策略上下文）→ RAG⑦ → **3 套策略并行生成⑧** → 案例对比⑨（并行）→ 风险深化⑩ → 叙事者⑪（异步）。全程 NDJSON 流式推送 AI 思考过程，策略卡打字机渲染（**以 done 终稿为准**——流式一稿在时长重试/审核修订后会被终稿整体替换）。

**策略生成四道防线**：① prompt 20 条铁律（阶梯性释放/时段常识/受控范围红线/时长表述与批次一致等）；② 确定性校验（时间升序/枚举合法/无船ID/防一次性全放，违规修复或判死回退规则模板）；③ **审核修订闭环**（独立审核员 7 条清单 → warn 带问题清单温度0.1重生成 → 复检，结论 self_check 落卡对值班员可见）；④ 全局一致性（三套时长排序 eff<act<zone±0.5h 违规重试、时间兜底=max(现在+2h,推荐窗口)、日期漂移净化）。

**降级路径**：LLM 不可达→策略回退规则模板（卡片标"规则模板"）、风险纯规则、叙事静默跳过；单套失败仅该套回退；缺核心气象（大风缺阵风/大雾缺能见度）→ 拒给解封时间与方案（missing_critical）。

## 三、数据（声明式配置，改策略不改代码）

- **matrix.yaml/json**：16 格 × 25+ 字段——controlled_ships（船型×禁航阈值）、release_mode、batch_count/interval/kv_batch/batch_ship_assign、trigger、及 11 个衍生维度（时间锚定/优先通行/窗口约束/跨域协同/决策权限/二次封航/校准案例等）
- **thresholds.yaml/json**：原因推断、级别判定（大风 Ⅰ=gust≥8…Ⅳ=5-6；大雾解禁 Ⅰ≥1500/Ⅱ≥1300/Ⅲ≥1600/Ⅳ≥1200m）、解禁前置核查（大风稳定 60/30min、阵风回落 Ⅰ/Ⅱ<6 Ⅲ/Ⅳ<5 级）
- **append_rules**：30+ 条原子条件 AND 规则（大雾凌晨 5-8 时暂缓、台风Ⅱ追加 24h 涌浪监测、凌晨 kv_tod×0.85 等）
- **prompts.json**：全部 prompt 收敛于此（conf/ 外置优先，MD5 热加载）——策略系统/审核/修订/叙事三段/四类解析/风险推演等 15+ key

## 四、《恶劣天气防抗指南》合规化（9/21-9/22 专项）

- **反推解封方案**：指南无解封专章，但管制阶梯逆读即得——阵风<7 解内河+万吨以下海船、<6 解江阴以下 80m 船+合规客渡、<5 全域全解；大雾按船型航向 1000/1500m 差异化；16 字疏导原则；8 小时联动（南京↔芜湖/太仓↔吴淞 VTS）。产出《解封方案反推》文档
- **阶梯解封（Python 版已实现，Java 待同步）**：forecast 输出 tiers（**同日达标档位归并为一个梯次**）+ fullRecovery；recommended 语义改为**首批解封时间**（首档达标日）；复核按启动日已达的最严档阈值（rec_thr）；研判卡加折叠梯次表、折线图档位线+◆梯次标记；策略/公文前端不变，档位只做后台批次时刻约束。备份 `_backup_py_before_tiers/` 可随时还原
- **已裁决修复**：大雾Ⅳ"80m+大船不受限/全程未管制"系从大风Ⅳ复制未改——按指南 §4.1（<1000m 禁所有船）已改为"解禁后优先疏导（效率），非未管制"
- **待客户拍板**：船型顺序按级别差异化（Ⅳ 先小船=指南16字且大船未被封 / Ⅱ·Ⅰ 先大船=巴威杜苏芮校准+抗风效率论 / 大雾按江海轮梯队=效率排序）；指南"稳定30min"无明文依据；案例库自身也存在"先小船后大船"实证（cases.json:467），冲突是活的

## 五、关键业务规则举例

- **大风Ⅳ**：仅 4 类受控（80m 以下小船/集装滚装易流态/拖带/汽渡旅游客），80m+ 大船不受限正常通航；一次性 5 梯队简化；批1 海轮="全程未管制优先通行"（≠解封）
- **大风Ⅱ（巴威校准）**：3 阶段风力阶梯推进（11:30 阵风7级放下行海轮→05:00 ≤6级加上行内河→10:00 5级全域），钟点锚定+稳定30min
- **大雾**：解禁视程多点稳定 30min；封航 300-700m/解禁 1200-1800m；凌晨辐射雾高发暂缓；江海轮 5 梯队（海轮第一=深水航道效率）；禁追越、靶向布锚、二次扎雾预案
- **暴雨Ⅰ（江淮特大暴雨校准）**：7 大专项核查；上游洪水未消退下游绝不放开上行
- **受控范围红线（铁律20）**：事件补充信息限定"仅80米以下受控"时，范围外船舶严禁出现在任何放行批次（约束走 prompt+自检，不做代码侧批次硬删——硬删会致 summary 与批次脱节）

## 六、部署

- **Python 研发版**：venv → pip install -e . → uvicorn :8000。LangGraph + Chroma + FastAPI + dashscope（qwen/deepseek 均可配）。无 Key 纯规则模式可跑。Windows 需 PYTHONUTF8=1
- **Java 交付版（主力）**：`java/` 目录，build.bat → haishi-ai.jar（JDK8 零依赖，内嵌 HTTP :8082/8000 可配），start-web.bat 起。配置 config.properties（内网 198.17.x LLM / 公网 dashscope 双套注释切换）；LLM 实际用 deepseek-v4-flash，全部专家共用一模型靠 prompt+温度分角色（策略 actual 0.2 / eff·zone 0.5 / 修订 0.1 / 审核 0.2）
- **SVN**（jyhs/ai/java）：与开发目录 E:\code\haishi 双向同步——改动先落开发目录（build/classes 优先读取），验证后拷 SVN 工作副本提交；曾发生 r36720 重构弄丢 predict 调用、r36725 双重受控范围处理致 summary 与批次脱节等事故，教训：**同步前 diff 全量核对**

## 七、经验沉淀

- "规则判分支 + LLM 组织 + 模板公文"三段职责分离是防幻觉的关键结构；公文（结构敏感）永不交 LLM
- **流式一稿与终稿一致性**：任何 emit 后的变异（重试/修订/过滤）都会造成卡片与公文脱节——前端以 done 终稿整体替换队列对象（一次修复兜住三类变异）
- 审核修订闭环（check→revise→recheck）只修一轮防烧预算，修订失败保留原版不倒退；确定性校验是底线（LLM 遵循 prompt 不可依赖，如"仅解封受控船舶"冗余标注最终靠代码剔除）
- 声明式 YAML/JSON 承载业务策略 + 热加载（conf/ 外置优先），改策略不改代码；但复制粘贴格间迁移易留错（大雾Ⅳ"大船不受限"教训）
- 指南/规范文本与案例校准数据可能冲突（16字原则 vs 大船优先）——先考古双方出处再按场景裁决，不二选一
- 踩坑：langchain-openai base_url 兼容（改 openai 直连）；dashscope embedding 单批≤10；LangGraph 节点名不能与 State key 同名；Windows COM 读 .doc 用 Word.Application；SVN blame/diff -c 定位肇事提交
- 配套：haishihoutai（后台+大屏，见 [haishihoutai](haishihoutai.md)）通过 HTTP 调本智能体；对话日志全量 E:/code/cclogs2
