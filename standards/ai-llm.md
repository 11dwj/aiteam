# LLM/AI 服务集成规范

基于 haishi 解封智能体与 seal-ai（智慧印章合规审查）的实战经验。

## 模型与配置（阿里云 DashScope）

- 模型：qwen-max / qwen-plus；temperature 0.3（生成类）
- 必须有**降级配置**：LLM 失败/超时降级到规则引擎或缓存模板，不阻断主流程

## 提示词硬约束（踩坑总结）

- 明确**字数限制**、**字段隔离**（输出只含指定字段）、**禁止填补性文字**（禁止"根据相关信息"这类编造）
- AI 输出包含内部指标信息会导致生成失败——提示词中显式禁止输出内部数据
- 提供真实样本 few-shot（haishi 用 19 份历史报告校准），不用编造示例

## 架构模式（haishi 模式）

1. 声明式规则：策略矩阵放 YAML（如 data/matrix.yaml），代码纯函数执行，不硬编码
2. RAG：Chroma 存历史案例，检索增强生成
3. **防御式校验**：生成结果过规则校验（R1 单批禁全放、R2 禁海船内河船合放、R3 必须阶梯式），任一违规整套拒收回退
4. badcase 闭环：上线后误判样本回流 → 加豁免规则/铁律 → 回归测试

## Java 侧（seal-ai 模式）

- 轻量 HTTP 服务（SimpleHttpServer + AliyunLLMClient），适合独立部署 jar（如 seal-ai.jar）
- 输入输出全量日志留存（合规审查需要审计）


## 海事智能体集群补充规范（2026-10）

- **模型链降级**：多条模型逗号分隔放配置，代码端按错误类型自动切换；见 knowledge/solutions.md AI/LLM 补充节
- **多模态分离**：视觉模型（图片/OCR）与文本模型分开配置键，互不影响可独立换用
- **文档解析分模式**：同一接口 + mode 参数（risk/daily/measure/standard/summary），每种模式独立提示词独立归一化，AI 只预填人工确认
- **枚举强校验**：提示词内嵌枚举清单，服务端归一化再做二次过滤（无效值→空串交人工补选，不硬归默认值）
- **确定性字段不交给 LLM**：日期等多来源字段用代码规则（文档>文件名>留空），LLM 值只当候选过合法性校验
- **审计留痕**：每次 LLM 调用记 JSONL（模型/哈希/耗时/ok），不含敏感内容；排查模型问题首选入口
