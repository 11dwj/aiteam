01 现有界面问题分析

基于 28 张小程序截图的系统性诊断

通过对首页、入场登记、装修申请/检查、生产计划、能源管理、巡查任务、资产管理、账单缴费等 28 个页面的截图分析，归纳出以下 7 类核心问题：

问题 1：按钮位置不统一

不同页面的提交/操作按钮位置不一致——部分页面按钮在底部固定栏，部分在页面底部正文流中，还有部分在右上角。用户在不同功能间切换时需要反复寻找操作入口。

改进方案：制定「底部固定操作栏」作为标准模式，全平台统一（详见第 16 章）
问题 2：卡片间距和圆角不一致

部分列表卡片间距 8px，部分 12px；圆角有的 4px、有的 8px、有的无圆角。视觉节奏断裂，缺乏统一感。

改进方案：统一卡片间距 12px、圆角 8px，建立 4px 基准间距系统
问题 3：状态标签样式混乱

「待审核」「已通过」「已完成」「待签收」等业务状态在各页面使用了不同的颜色、字号和形状（方形/圆角/无底色），无法形成一眼可辨的状态语义体系。

改进方案：建立 5 色语义状态标签体系（成功/警告/错误/信息/默认），全平台复用
问题 4：导航栏细节不统一

所有页面运行在微信小程序 WebView 中，上方为微信原生框架（状态栏 + 胶囊按钮），下方为 H5 自渲染标题栏。H5 标题栏统一使用品牌蓝底 + 白色标题。

改进方案：统一 H5 标题栏——品牌蓝背景 + 白色标题居中 + 白色返回箭头；上方微信原生框架由微信控制，无需处理
问题 5：表单字段缺乏分组

装修申请、生产计划等表单页面字段密集且缺少视觉分组，必填项标识不明显，用户难以快速扫描和理解信息结构。

改进方案：表单按业务逻辑分区，每区有标题分隔线；必填项用红色 * 明确标识
问题 6：详情页信息层级模糊

关键信息（如企业名称、审批状态）和次要信息（如时间、编号）的字号和字重差异不够大，用户需要逐行阅读才能定位关键数据。

改进方案：建立 4 级文字层级体系——标题16px/600 → 正文14px/500 → 辅助12px/400 → 说明10px/400
问题 7：能源/数据统计页面缺少可视化引导

能源统计、账单等数据展示页面信息密度高，缺少图表和趋势可视化，数字呈现方式单调（纯文本列表），不利于快速理解数据走势。

改进方案：统计数据使用卡片+数字突出展示，配色区分能源类型（电-蓝/水-青/气-橙）

02 设计原则

工业风格 + 政务严谨 + 移动优先

2.1 产品定位

本小程序服务于电镀产业园区的日常运营管理，用户群体包括园区工作人员（巡查、检查、审批）和入驻企业（申请、缴费、整改）。界面设计需要满足：

维度要求说明
专业性政务级严谨配色沉稳、布局规整、数据准确
效率高频操作优先核心功能 ≤ 2 次点击触达
可读性户外/厂房可用对比度 ≥ 4.5:1，最小可点击区域 44px
一致性全平台统一同一操作在各页面表现完全一致

2.2 五项核心原则

原则一：统一优先

所有页面的导航栏、按钮、卡片、间距、圆角、色彩必须严格遵循设计令牌。禁止同一功能在不同页面出现不同的视觉表现。一致性是工业园区管理工具的第一视觉品质。

原则二：操作在底

主要操作按钮（提交、审核、下一步）一律放置于底部固定操作栏，高度 56px+安全区域。用户拇指自然可达，无需页面滚动即可完成关键操作。

原则三：信息分层

每个页面/卡片必须有明确的信息优先级：第一眼看到标题+状态，第二眼看到关键数据，第三眼看到辅助信息。通过字号、字重、颜色的差异实现层级，而非通过间距堆叠。

原则四：状态语义化

所有业务状态用统一的 5 色语义体系表达：绿色=成功/通过、橙色=待处理/警告、红色=错误/驳回、蓝色=进行中/信息、灰色=默认/已完成。同一含义的颜色在任何页面都不变。

原则五：安全防误

关键操作（审批通过/驳回、删除、提交申请）必须二次确认。驳回、退回操作需要填写原因。表单提交前做必填校验，错误提示在字段下方红色显示。

09a 页面示例：带操作列表页

16 按钮位置统一规范

解决当前最突出的按钮位置不一致问题
核心问题回顾：需求变更记录中明确指出「按钮风格不统一，提交的一会在下面，一会在右上角」。这是当前 UI 最大的体验痛点，本规范将其作为第一优先级整改项。

16.1 统一规则：底部固定操作栏

所有需要用户执行操作的页面（详情页、表单页、检查页），主操作按钮一律放在底部固定操作栏，高度 56px + 底部安全区域。

页面类型按钮位置布局
详情页（需审批）底部固定栏左：退回(危险) 右：通过(主要)
表单页（需提交）底部固定栏左：暂存(次要) 右：提交(主要)
检查页（需提交）底部固定栏左：退回整改(危险) 右：提交检查(主要)
数据页（需缴费）底部固定栏通栏主按钮
列表页（纯浏览）无底部栏如有新增，右下角浮动按钮(FAB)
列表页（可筛选）右上角导航栏筛选图标在导航栏右侧

16.2 按钮层级规范

层级样式使用场景出现位置
第一优先主要按钮（蓝色填充）提交、通过、缴费底部栏最右侧
第二优先次要按钮（蓝色描边）暂存、取消、返回底部栏左侧
第三优先危险按钮（红色填充）驳回、退回、删除底部栏左侧
页面内操作幽灵按钮（无填充）筛选、排序、展开内容区域内联
导航栏操作文字按钮（白色）更多、筛选、导出导航栏右侧

16.3 禁止行为清单

禁止行为原因正确做法
提交按钮在页面内容流最底部用户需滚到底部才能操作固定在底部操作栏
同页面多种按钮风格混用视觉混乱，降低专业感同一页面最多 2 种按钮类型
右上角提交按钮+底部无按钮不符合移动端拇指操作习惯统一到底部操作栏
按钮文字过长(>6字)破坏按钮视觉平衡精简为 2-4 字
按钮高度不一致视觉不齐整统一 48px(大)/40px(中)/32px(小)
实施建议：建议在全平台范围内先统一底部操作栏这一项，即可显著改善体验一致性。其余组件规范可按模块逐步迭代落地。
