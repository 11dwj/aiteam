# 提示词优化规范

参考 AiShort、StyleKit、promptlab 三个提示词库的最佳实践，适用于 codeteam 所有角色文档、skill、以及给客户的 LLM 提示词（配合 [ai-llm.md](ai-llm.md)）。

## 一、统一书写结构（所有角色/提示词必须五段齐全）

```markdown
# 角色：{名称}

你是{一句话角色定位}。            ← 角色前缀，明确"act as"

## 输入（Input）
- {{变量名}}：说明期望内容        ← 中文/双花括号占位，禁止留模糊口语句

## 职责
{做什么，动词开头，逐条列}

## 约束清单
- {按任务维度的固定检查项}        ← 见下方"约束维度表"

## 输出契约
- 格式：{markdown 表格 / diff / JSON…}
- 语言：中文（或指定）
- 禁止项：{如"不要解释过程"、"不要笼统说'完成'"}

## 示例
Input：…
Output：…                        ← 至少 1 组 Input→Output 标注示例
```

## 二、约束维度表（按任务类型选固定检查清单，不写泛描述）

| 任务类型 | 固定约束四栏 |
|---|---|
| 前端/UI | 数据 / 布局 / 交互 / 响应式（StyleKit 范式） |
| 后端 | 分层位置 / 事务与异常 / 权限 / 兼容性 |
| SQL | 幂等 / 备份 / 影响行数 / 方言（MySQL vs 金仓PG） |
| AI/LLM | 字数限制 / 字段隔离 / 禁填补性文字 / 失败降级 |
| 测试 | 真实入口 / 命令 / 断言 / 证据，五态状态 |
| 文案/公文 | 格式模板 / 语体 / 禁内部数据 |

## 三、输出约束显式化（三家共性，最重要）

- "只输出 X，不要解释过程"
- 代码修复类：给出**可直接采纳的 diff**，不只描述思路
- 终端/解释器类：只回运行结果
- 评审类：逐条过（如可读性/边界/性能），每条给结论+证据

## 四、工具分工矩阵（规划 vs 实施分层）

| 场景 | 用途 |
|---|---|
| 对话模型（无代码权限） | 实现前梳理页面结构、视觉方向、方案对比 |
| Claude Code / Codex | 转成真实组件、代码级迭代、代码库内实现与验证 |

对应团队分层：**策划/设计角色先出结构与方向 → 开发角色落地实现**，不越层。

## 五、元提示词（提示词优化器）

把"模糊需求 → 结构化提示词"本身作为一个能力：用户给了模糊一句话需求时，先改写成符合本规范五段结构的提示词（变量显式化、约束按维度表补齐、输出契约明确），确认后再执行。

## 六、示例反哺（Previews 模式）

把已经验收过的真实产物（页面模板、SQL 脚本、公文）作为**结构参考**，把其区块、布局、交互状态写回提示词，让下次输出更稳定。团队落地：优秀产出归档到 knowledge/，角色示例区直接引用归档路径。
